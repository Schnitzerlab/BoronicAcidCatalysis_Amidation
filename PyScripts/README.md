# BoronicAcidCatalysis_Amidation

Reproducible Python workflow for descriptor generation, machine-learning model development, TabPFN prediction of virtual arylboronic-acid libraries, and the applicability-domain and baseline-benchmarking analyses used for the project **Data-Driven Discovery of Boronic Acid Catalysts for Amidation Reactions**.

This README is intentionally written for users who are comfortable with synthetic/physical organic chemistry but do **not** need to be experienced Python or machine-learning programmers. The commands can be copied directly into the IPython console in Spyder. Equivalent terminal commands are also shown.

---

## 1. What is in this repository?

The workflow contains **15 numbered steps**. Step 08 is divided into `08a` and `08b`, so the `scripts/` folder contains 16 executable workflow scripts plus the shared helper file `common.py`.

```text
scripts/
├── 01_generate_library.py
├── 02_prepare_dataset.py
├── 03_generate_conformers.py
├── 04_run_pm3.py
├── 05_select_pm3_conformers.py
├── 06_run_dft_geometry.py
├── 07_run_vertical_ip_ea.py
├── 08a_generate_substituent_features.py
├── 08b_extract_features.py
├── 09_train_classical_models.py
├── 10_train_tabpfn.py
├── 11_apply_models.py
├── 12_rank_predictions.py
├── 13_tanimoto_mae.py
├── 14_benchmarking.py
├── 15_spearman_analysis.py
└── common.py
```

`common.py` **must remain in the same `scripts/` folder as the numbered scripts**, because the workflow imports shared functions from it and uses its location to determine the repository root.

Conceptually, the workflow is divided into four blocks:

```text
01–08b   Structure/library generation and molecular descriptors
09–10    Model development and TabPFN train/test evaluation
11–12    Final full-data TabPFN prediction and ranking of virtual libraries
13–15    Applicability-domain, baseline, and rank-correlation analyses
```

## 7. Step 03 — Generate molecular conformers

### Purpose

For each molecule, up to 20 three-dimensional conformers are embedded with RDKit ETKDGv3 using RMSD pruning (`0.5 Å` by default). MMFF94 relaxation is attempted when RDKit parameters are available.

For boron-containing molecules, MMFF94 parameters may be unavailable. This is **not automatically an error**. In that case, the ETKDG geometry is retained and passed to the PM3 optimization, and this is recorded in the QC table.

### Run for the training library

```python
%run scripts/03_generate_conformers.py --dataset training
```

Then repeat for the virtual libraries:

```python
%run scripts/03_generate_conformers.py --dataset mono_library
%run scripts/03_generate_conformers.py --dataset di_library
```

### Important defaults

```text
Maximum conformers:       20
RDKit random seed:        42
RMSD pruning threshold:   0.5 Å
```

### Output

```text
work/<dataset>/01_conformers/*.xyz
work/<dataset>/01_conformers/conformer_generation.csv
```

### QC

Open `conformer_generation.csv` and inspect failed embeddings and MMFF availability. A missing MMFF parameter set for a boronic acid does not invalidate the conformer; failed RDKit embedding does.

## 12. Step 08a — Position-specific substituent descriptors

### Purpose

Step 08a automatically identifies the phenyl ring attached to the primary boronic-acid unit, determines substituents at positions 2–6, and generates the position-specific descriptors used by the ML workflow.

For each position the final feature table contains:

```text
2_binary ... 6_binary
Molmasse_2 ... Molmasse_6
VdW_2 ... VdW_6
BV_2 ... BV_6
```

Each unique substituent is represented by a phenyl-capped model. The model is embedded in 3D, pre-relaxed with UFF, optimized with PM3/ORCA, and used to calculate substituent mass, van-der-Waals volume, and buried-volume descriptors. Unique substituents are cached and therefore do not need to be recalculated for every library molecule.

Unsubstituted positions are represented by the hydrogen reference values encoded in the script.

### Full run

```python
%run scripts/08a_generate_substituent_features.py --dataset training
```

Repeat for the virtual libraries.

### Optional preparation-only test

To check substituent recognition and capped structures without launching ORCA:

```python
%run scripts/08a_generate_substituent_features.py \
    --dataset training \
    --prepare-only
```

### Output

```text
work/<dataset>/07_substituent_features/substitution_assignment.xlsx
work/<dataset>/07_substituent_features/substitution_qc.csv
work/<dataset>/07_substituent_features/substituent_descriptor_library_used.xlsx
work/<dataset>/07_substituent_features/substituent_features.xlsx
```

A reusable cache is stored under:

```text

```

### QC

Inspect `substitution_qc.csv`. Failed substituent calculations are **not silently replaced by hydrogen values**; missing PM3-derived descriptor values remain missing and should be investigated.

# PART II — Model development

## 14. Step 09 — Classical model grid

### Purpose

Step 09 executes the complete classical model-development grid in a single reproducible script.

Four model families are evaluated:

```text
Decision Tree
Random Forest
Gradient Boosting
XGBoost
```

Two hyperparameter-optimization approaches are used:

```text
RandomizedSearchCV
Optuna
```

Eight feature-selection approaches are used:

```text
RFE: 3, 5, 7, 10, or 15 features
RFECV
embedded feature importance
Boruta
```

This gives:

```text
4 models × 2 tuning approaches × 8 selectors = 64 workflows
```

The default classical split is 80:20 with random seed 42. Feature selection is fitted on the training data only. Hyperparameter optimization is performed only inside the training set using 5-fold CV. The held-out test set is used only for final evaluation.

### Exact ML-reproduction command

```python
%run scripts/09_train_classical_models.py \
    --input data/training/training_data.xlsx \
    --output results/classical_models \
    --split-mode row \
    --progress
```

The default search sizes are large:

```text
RandomizedSearchCV iterations: 2000
Optuna trials:                 1000
```

Therefore, the full grid can take substantial time.

### Small test run

Before starting the entire grid, a small subset can be run, for example:

## 15. Step 10 — Seven-split TabPFN evaluation

### Purpose

Step 10 assesses TabPFN performance and robustness across seven independent row-wise 80:20 train/test splits.

The exact split seeds used by the final scripts are:

```text
3
43
99
604
1704
2005
2508
```

For each split:

1. the 80:20 split is generated from the same input row order;
2. missing descriptor values are median-imputed using **training data only**;
3. a `RobustScaler(quantile_range=(5, 95))` is fitted using **training data only**;
4. `TunedTabPFNRegressor` is optimized with RMSE as the HPO metric;
5. the HPO/model `random_state` is equal to the corresponding split seed;
6. R², RMSE, and MAE are calculated on the held-out test set.

The current executed workflow uses **one HPO trial per split** (`--n-trials 1`). This is intentional and should be stated consistently in the SI.

### Run

```python
%run scripts/10_train_tabpfn.py \
    --input data/training/training_data.xlsx \
    --output results/tabpfn \
    --n-trials 1
```

### Output

For each seed:

```text
results/tabpfn/split_<seed>/metrics.csv
results/tabpfn/split_<seed>/predictions_test.csv
results/tabpfn/split_<seed>/best_hyperparameters.csv    (when HPO succeeds)
results/tabpfn/split_<seed>/real_vs_predicted.svg
results/tabpfn/split_<seed>/parity_test.png
results/tabpfn/split_<seed>/residuals_test.png
```

Across all seeds:

# PART IV — Reviewer-requested analyses

## 18. Step 13 — Tanimoto similarity versus prediction error

### Purpose

Step 13 evaluates whether TabPFN prediction error depends on structural similarity to the training set.

For each of the seven held-out test splits from step 10, the script reconstructs the exact training/test membership from the master table and split seed, and verifies this membership against `predictions_test.csv`.

For every test catalyst it calculates:

- Morgan fingerprint with radius 2 and 2048 bits;
- maximum Tanimoto similarity to any molecule in the corresponding training set;
- nearest training molecule;
- signed prediction error;
- absolute prediction error.

It then calculates the Spearman correlation between maximum training-set similarity and absolute prediction error and summarizes MAE in predefined similarity bins:

```text
<0.40
0.40–0.50
0.50–0.60
0.60–0.70
0.70–0.80
≥0.80
```

These bins are fixed in advance rather than optimized after seeing the data.

### Run

```python
%run scripts/13_tanimoto_mae.py \
    --data data/training/training_data.xlsx \
    --tabpfn-results results/tabpfn \
    --output results/reviewer/tanimoto
```

### Optional named targets

An optional target file can be supplied to calculate training-set similarity for compounds such as FIBA, MIBA, or DBA. The table should contain at least:

```text
SMILES
```

and may additionally contain `Label` or `Molecule`.

Example:

```python
%run scripts/13_tanimoto_mae.py \
    --data data/training/training_data.xlsx \
    --tabpfn-results results/tabpfn \
    --output results/reviewer/tanimoto \
    --targets data/reviewer/target_compounds.xlsx
```

Exact self-matches are excluded for this named-target analysis.

### Output

```text
results/reviewer/tanimoto/Tanimoto_vs_MAE.xlsx
results/reviewer/tanimoto/Tanimoto_vs_MAE_all_points.csv
results/reviewer/tanimoto/Error_vs_Tanimoto.png

```

If targets are supplied:

```text

```

### QC

The script intentionally refuses to run the final applicability-domain analysis if exact structural duplicates remain in the master dataset. This prevents an identical structure from artificially giving a test compound a Tanimoto similarity of 1.0 to the training set.

## 19. Step 14 — Benchmark TabPFN against simple baselines

### Purpose

Step 14 compares TabPFN with deliberately simple baselines that ask whether the ML model provides information beyond structural nearest-neighbour matching, a straightforward ortho-substitution rule, or random selection.

The compared methods are:

```text
1. TabPFN
2. 1-nearest-neighbour (1-NN) using Morgan/Tanimoto similarity
3. Ortho-halogen heuristic
4. Random ranking baseline
```

### Ortho-halogen heuristic

The heuristic assigns the following ranking score relative to the aryl–boron bond:

```text
no ortho substituent       0
other ortho substituent    1
ortho-F                    2
ortho-Cl                   3
ortho-Br                   4
ortho-I                    5
```

If more than one ortho substituent is present, the highest applicable score is used. Ties are repeatedly randomized so that top-k metrics are not determined by arbitrary row order.

### Metrics

For TabPFN and 1-NN, the script reports continuous regression metrics:

```text
R²
MAE
RMSE
```

For all four ranking approaches it evaluates the experimentally defined top 10% and top 20% of the test set using:

```text
Hits@k
Precision@k
Enrichment Factor@k
Top-k success
ROC-AUC
PR-AUC
```

The random baseline is averaged over 5000 repetitions by default. Ortho-heuristic tie breaking is averaged over 2000 repetitions. The benchmarking random seed is 42.

## 20. Step 15 — Spearman rank correlation between experimental and predicted conversion

### Purpose

Step 15 provides a compact rank-based summary of how well the TabPFN predictions reproduce the experimental ordering of catalysts in each of the seven held-out test splits.

This analysis is **different from the Spearman analysis in step 13**:

```text
Step 13: Spearman correlation between Tanimoto similarity and absolute prediction error
Step 15: Spearman correlation between experimental conversion (y_true) and predicted conversion (y_pred)
```

The script reads the native `predictions_test.csv` files written by step 10 directly. No intermediate Excel workbook has to be assembled manually.

For each split, `scipy.stats.spearmanr` is used to calculate Spearman's rank-correlation coefficient (ρ) between `y_true` and `y_pred`. Tied values are handled by the standard average-rank procedure used by SciPy. The seven split-level ρ values are then summarized by their arithmetic mean and the **sample standard deviation (n − 1)**.

### Run

```python
%run scripts/15_spearman_analysis.py \
    --input results/tabpfn \
    --output results/reviewer/spearman
```

The input folder must contain the step-10 outputs:

```text

├── split_3/predictions_test.csv
├── split_43/predictions_test.csv
├── split_99/predictions_test.csv
├── split_604/predictions_test.csv
├── split_1704/predictions_test.csv
├── split_2005/predictions_test.csv
└── split_2508/predictions_test.csv
```

By default, the script requires exactly seven split files. For a temporary test with a different number of splits, this check can be disabled with:

```python

```

### Output

```text

```

The console additionally prints every split-level ρ value and the final mean ± sample SD.

### QC

The script stops if a split prediction file is missing `y_true` or `y_pred`, contains missing/non-numeric/non-finite values, or contains a constant `y_true` or `y_pred` column for which Spearman correlation is undefined. It also checks that the expected number of split files is present.


# 21. Practical troubleshooting

### `File ... not found`

Most often, Spyder is in the wrong working directory. Run:

```python
%cd /path/to/BoronicAcidCatalysis_Amidation
```

and retry.

### ORCA executable not found

Set:

```python
import os
os.environ["ORCA_EXE"] = "/path/to/orca"
```

or use `--orca /path/to/orca` for the ORCA-running scripts.

### MMFF parameters unavailable

This is common for boron-containing molecules. Step 03 records this and retains the ETKDG geometry for subsequent PM3 optimization.

### A TabPFN seed takes much longer than the others

Runtime can vary strongly with seed/HPO configuration. If the process is still using CPU and no exception has appeared, this does not necessarily indicate a failure.

### TabPFN HPO failure

Steps 10 and 11 contain a fallback to plain TabPFN. For final publication calculations, inspect the output and make sure the intended HPO procedure succeeded for all runs rather than silently accepting a fallback.
